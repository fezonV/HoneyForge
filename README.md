# HoneyForge — заготовка за вечер

Один Go-сервис: фиктивный внутренний архив, журнал запросов в памяти и HTML-панель. Только стандартная библиотека Go, HTML и JavaScript.

## Запуск

Нужен Go 1.22 или новее. Из папки проекта:

```sh
go run .
```

Ловушка: http://127.0.0.1:8080/ — панель: http://127.0.0.1:8080/dashboard.
Остановить сервер: `Ctrl+C`. Если порт занят: `go run . -addr 127.0.0.1:8081`.

## Проверка за минуту

1. Откройте `/dashboard`: журнал пустой.
2. Нажмите «Открыть ловушку», затем «Отчёты подразделений».
3. Вернитесь в панель: появятся запросы `/` и `/reports`, с временем, IP и методом. При нормальной связи обновление занимает около двух секунд.
4. Перезагрузка панели и запросы `/api/events` не добавляют событий.
5. Перезапустите сервер: журнал снова пустой.

Можно отправить запрос из терминала Windows:

```powershell
Invoke-WebRequest http://127.0.0.1:8080/demo
Invoke-RestMethod http://127.0.0.1:8080/api/events
```

## Как устроено

- `main.go` — HTTP-сервер и защищённый mutex журнал последних 100 событий; новые события выдаются первыми.
- `archive.html` — фиктивный каталог. Разделы возвращают ту же страницу: настоящих файлов и авторизации здесь нет.
- `dashboard.html` — таблица, опрашивающая `GET /api/events` каждые две секунды. JSON — массив объектов с полями `time` (UTC), `ip`, `method`, `path`.

Страницы встроены в Go-приложение. Все пути вне `/dashboard`, `/dashboard/…` и `/api/…` считаются обращениями к ловушке. Query-параметры, тела и заголовки не сохраняются. IP берётся из сетевого соединения, заголовки прокси не используются.

Это локальная демонстрация: журнал живёт только до перезапуска, панели нет авторизации, слушаем `127.0.0.1`. Удалённые агенты, постоянное хранение и управление ловушками — следующий этап. Предложения по будущей системе собраны в `AGENTS.md`; они не описывают реализованные возможности. Подробный локальный план лежит в `docs/HONEYFORGE_PLAN.md` и исключён из Git.
