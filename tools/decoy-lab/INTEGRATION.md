# Граница компонентов и подключение

## PreviewModel

Это внутренний формат представления лаборатории, **не утверждённый Profile/API HoneyForge**. Модель существует только в памяти текущей вкладки. Шаблоны не знают адрес центра, не обращаются к сети или browser storage, не создают события и не проверяют credentials/права.

```js
const model = {
  organization: 'Вереск',
  service: 'Корпоративный архив',
  title: 'Документы организации',
  description: 'Регламенты, отчёты и служебные заметки.',
  sections: ['Регламенты'],
  documents: [{
    id: 'rules',
    section: 'Регламенты',
    title: 'Порядок ведения архива',
    path: '/regulations/archive-rules.txt',
    date: '2026-09-01',
    body: 'Синтетический текст регламента.'
  }],
  state: 'files',
  selectedDocumentId: 'rules'
};
```

Текстовые поля — строки. `sections` определяет порядок групп; `document.section` должен совпадать с одной из них. `documents` — массив текстовых документов с уникальными стабильными `id`. Редактирование названия/пути не меняет `id`, поэтому просмотр остаётся связан с выбранным документом. `date` — календарная дата `YYYY-MM-DD`; неполная/пустая дата отображается текстом. Размер вычисляется из `body` через UTF-8 `TextEncoder`, а не хранится отдельным полем. Пустые названия файлов получают подпись «Без названия».

`path` — исключительно подпись: не используется в `href`, запросах, обработчиках маршрутов или чтении FS. Модель не содержит URL центра, secrets, credentials, HTML, схемы событий или назначенного профиля. Данные передаются через `textContent`, не `innerHTML`. Подключающий адаптер отвечает за полноту и валидацию модели; шаблоны не выполняют серверную валидацию.

## Входы и состояния

Оба компонента экспортируют синхронную функцию `renderLow(root, model, handlers)` / `renderMedium(root, model, handlers)`. `root` — DOM-элемент; его содержимое заменяется при каждом вызове. Узлы создаются через `root.ownerDocument`, поэтому компоненты работают как в обычном документе, так и в отдельном iframe. Для внешнего оформления нужен `assets/archive.css`.

| Шаблон | `state` | Отображение |
|---|---|---|
| Low | `catalog` | Разделы и список документов |
| Low | `empty` | Пустой архив |
| Low | `not-found` | Согласованная страница «Не найдено» |
| Low | `unavailable` | Статический ответ для недоступного материала |
| Medium | `login` | Макет входа |
| Medium | `login-error` | Макет входа с ошибкой |
| Medium | `files` | Список файлов |
| Medium | `file` | Текст документа по `selectedDocumentId` |
| Medium | `empty` | Пустой каталог |
| Medium | `expired` | Сообщение об истёкшей сессии и макет входа |

При неизвестном `selectedDocumentId` Medium показывает «Файл не найден» с возвратом. Адаптер должен передавать одно из перечисленных состояний: неизвестное состояние сейчас отображает каталог. Пустое состояние выбирает оболочка; массив документов при этом остаётся доступен редактору.

Все состояния Medium — иллюстрация. `files` и `file` не доказывают успешный вход. Поля входа `readonly`, кнопка `disabled`, формы и проверки пароля отсутствуют. При подключении к реальному decoy владельцы #3/#9 должны заменить этот макет согласованной серверной формой; включать кнопку без реализации серверного поведения нельзя.

## Намерения и обработчики

| Компонент | Обработчик | Когда вызывается |
|---|---|---|
| Low | `unavailable(documentId)` | Нажатие названия документа; оболочка показывает статический ответ |
| Low | `showCatalog()` | Возврат из пустого/недоступного/не найденного состояния |
| Medium | `openFile(documentId)` | Нажатие названия файла |
| Medium | `showFiles()` | Возврат к списку файлов |
| Medium | `logout()` | Нажатие «Выйти» в списке/просмотре/пустом каталоге |

Обработчики необязательны; компонент не изменяет модель самостоятельно. В лаборатории они только меняют локальный экран и сообщение оболочки. `logout` не отзывает сессию. При замене DOM оболочка переносит фокус на заголовок, если инициатор действия находился внутри предпросмотра; другой потребитель должен самостоятельно сохранить понятный порядок фокуса.

## Пример на локальных данных

Запустить статический сервер. В HTML добавить `<link rel="stylesheet" href="assets/archive.css">` и `<div id="archive"></div>`. Затем подключить модуль:

```js
import { createExample } from './fixtures/example.js';
import { renderMedium } from './templates/medium.js';

const root = document.getElementById('archive');
const view = { ...createExample(), state: 'files', selectedDocumentId: 'rules' };
const handlers = {
  openFile(id) {
    view.selectedDocumentId = id;
    view.state = 'file';
    draw();
  },
  showFiles() {
    view.state = 'files';
    draw();
  },
  logout() {
    view.state = 'login'; // Только локальная смена экрана.
    draw();
  }
};
function draw() {
  renderMedium(root, view, handlers);
}
draw();
```

Пример не требует iframe. Sandbox — свойство оболочки лаборатории, а не обязанность потребителя отображения. Два компонента могут сосуществовать в разных корнях; для двух макетов входа в одном document адаптеру нужны отдельные документы/iframe или уникальные идентификаторы полей.

## Ответственность последующей интеграции

- **#7:** форма конструктора, права, валидация, сохранение через принятый API, адаптация данных в PreviewModel. Пока передачи нет — временная заглушка. Локальные изменения не должны выдавать результат «применено».
- **#9:** адаптация/размещение шаблонов в реальном decoy, формы входа/выхода, скачивание, дополнительные экраны и интерфейс фиксированных псевдокоманд вместе с #3.
- **#3:** маршруты, настоящие изолированные сессии, доступ к синтетическому fake-FS, серверные действия и события.
- **Владелец лаборатории:** компоненты и изменения внутренней модели в этом каталоге. Владельцы #7/#9 пишут адаптеры к согласованным контрактам #1/#3. Лаборатория не навязывает URL, Profile/API, способ серверной шаблонизации или Go-структуры.

До подключения нужно согласовать: реальные маршруты и ссылки; отображение ошибок и срок жизни сессии; какие файлы разрешены для конкретного профиля; источник названий/дат/размеров; набор событий и связь с session/event ID; границу чувствительных данных; серверное экранирование; фокус после навигации; поведение скачивания и псевдокоманд. Пути из модели не должны напрямую разрешаться в FS хоста.

В рабочую приманку не включать `index.html`, `lab.js`, `lab.css`, редактор, demo-переключатели и служебную пометку лаборатории. Не переносить фиктивную авторизацию. Данные рабочего интерфейса берутся из применённого профиля, а состояние — из подтверждённого серверного результата. Подключение к #3/#7/#9 не является критерием локального завершения #18.
