# FE2-04: dashboard, аудит и серверный CSV

Ветка `codex/fe2-04` создана поверх FE2-03 (`f937f8d`). Проверены контракты
текущего `dev` и изменения `origin/codex/be04-complete` (`c965431`): размещение UI
за reverse proxy сохраняет те же REST/WS endpoints. Ветка BE-04 не объединялась.

## Реализация

- Dashboard запрашивает полный парк, агрегат выбранного периода, агрегат
  предыдущего периода и последние 10 событий независимо. Один сбой не скрывает
  остальные данные. При повторном чтении остаётся предыдущий снимок с явной
  отметкой устаревания; при смене периода старые значения убираются.
- Период задаётся в UTC и сохраняется в URL. Быстрый выбор: 1 час, 24 часа,
  7 дней. Обновление снимков сохраняет выбранные границы. Динамика — абсолютное
  и процентное сравнение с предыдущим периодом; при нулевой базе процент не
  выдумывается. Границы включительные; предыдущая заканчивается за микросекунду
  до текущей с учётом точности PostgreSQL, без двойного подсчёта граничного события.
- Показатели количества/типов событий, предыдущий период и top IP ведут в
  журнал с теми же фильтрами. Последние события ведут в отдельные детали FE2-03.
  Online/offline/degraded ведут в согласованный фильтр парка. Degraded —
  service_state error/degraded или telemetry.degraded, может пересекаться с
  online/offline. Состояние парка относится к моменту снимка, не к истории периода.
- Виден канал WS, last_seen и присланные метрики очереди, карантина, доставки,
  повторов и хранилища. Отсутствующие значения обозначаются «Неизвестно».
  Страна/ASN показываются только из серверного обогащения; фиктивной карты нет.
  Обращения не называются подтверждёнными атаками.
- Аудит доступен operator: время UTC, фактический actor_id, действие, объект,
  результат записи и безопасные подробности. Фильтры action/actor_id/from/to
  выполняются сервером, cursor по 50 строк сохраняется в URL. Есть ссылки на
  ловушку, профиль, событие и экземпляр команды. Неизвестные роли/имена не
  подставляются. Отсутствующий actor_id обозначает серверное действие/агента.
- Для command.queued отдельно запрашивается текущее состояние через историю
  команд, включая failed/expired и причину. Историческая запись queued остаётся
  queued; исполнение не имитируется. Из аудита открывается карточка профиля;
  удалённый/недоступный профиль показан явно.
- CSV в журнале и dashboard запрашивается через backend для всех шести активных
  фильтров. Cursor и размер видимой страницы не передаются. Лимит — 10 000 строк;
  при превышении сервер отклоняет экспорт, UI предлагает сузить выборку.
  Есть состояние выполнения, защита от повторного нажатия, ошибки и отмена при
  смене фильтров/выходе. Payload/credentials не экспортируются. Роль viewer не
  получает кнопку; прямой запрос запрещается сервером. Формулы нейтрализует backend.

## Ручная приёмка

1. Запустите центр, PostgreSQL и UI по `web/README.md`. Войдите в режиме API.
   Запустите Low/Medium по существующей инструкции парка.
2. На «Обзоре» выберите UTC-период, создайте обращения к ловушкам и нажмите
   «Обновить сводку». Сверьте количество с `/api/v1/events/summary?from=…&to=…`.
3. Перейдите по общему числу, типу события и top IP. В журнале должны сохраниться
   период и соответствующий фильтр. Online/offline/degraded открывают парк.
4. Отключите один запрос через DevTools и обновите сводку: остальные виджеты
   доступны, старый снимок отмечен. Новый период не наследует старые числа.
5. В журнале задайте фильтры и перейдите на старую страницу. Скачайте CSV:
   выгрузка должна включать всю серверную выборку. Проверьте отсутствие секретов.
6. Измените профиль, назначьте версию экземпляру, отправьте команду. В «Аудите»
   отфильтруйте свой actor_id/действие/период. Проверьте объекты и ссылки;
   для команды нажмите «Проверить результат команды».
7. Войдите как viewer: аудит закрыт, CSV недоступен. Прямые API также дают 403.
8. Пройдите фильтры, ссылки и кнопки клавишами Tab/Enter; проверьте 1280×720
   и 1440×900. Таблицы допускают горизонтальную прокрутку.

## Что остаётся после интеграции

Нужно повторить целевую TLS/reverse proxy и общую приёмку после объединения
BE-04, BE-02 и FE2-03/04, включая latency из #15 и комплект сдачи #17.
Текущая локальная проверка не является production gate.

Backend не записывает финальные command.applied/failed/expired в audit_log:
UI получает текущий результат отдельно из commands. Для исторического аудита
именно переходов исполнения нужны серверные записи этих переходов в транзакциях
и соответствующий контракт. Имена операторов потребуют серверного справочника
пользователей или actor snapshot; сейчас честно показан actor_id. Geo/ASN требуют
настроенных серверных баз обогащения. Автоправила, уведомления и STIX относятся
к отдельным бонусам FR-C7.
